# ADR-0003. Живое превью без временных файлов

- **Статус:** принято (вступает в силу в M1)
- **Дата:** 2026-09-19
- **Контекст:** прототип генерирует `temp_preview.png` в рабочей папке приложения, затем читает его как `BitmapImage`. Из этого следуют проблемы:

  - файл-артефакт попадает в git (`temp_preview.png` в корне репозитория);
  - превью и экспорт — два прохода записи/чтения файла, лишние задержки и ошибки ввода-вывода;
  - при быстрых изменениях параметров возможны гонки на файле;
  - «живое» обновление невозможно: каждая перерисовка — это полный цикл записи файла;
  - зум реализован `ScaleTransform` поверх растровой картинки, то есть качество превью зависит от того, в каком разрешении его сохранили.

## Решение

Превью не касается диска:

- сцена после раскладки хранится в памяти;
- `SKElement` рисует сцену при каждом `PaintSurface` в разрешении окна;
- панорама и зум меняют только `Viewport` и вызывают перерисовку, не пересчитывая сцену;
- файл пишется только по явной команде «Экспорт» — сразу в целевом разрешении;
- `temp_preview.png` удаляется из репозитория и из `.gitignore`-исключений (шаблон png-превью добавляется в ignore).

## Последствия

Проще:

- нет гонок и мусора на диске;
- превью всегда в нативном разрешении экрана, зум — настоящий;
- изменение параметров видно сразу;
- экспорт не зависит от того, что показывалось в окне.

Сложнее:

- сцена живёт в памяти (для 10^8 чисел в память попадёт только сцена видимого/выбранного диапазона — диапазон задаёт пользователь);
- нужен контроль аллокаций, чтобы `PaintSurface` не создавал мусор;
- превью-контрол должен уметь переживать смену сцены в фоне (потокобезопасная подмена ссылки).

Задачи:

- удалить `LoadPreviewImage` и всё, что связано с временным файлом ([ui.md](../ui.md));
- добавить в `.gitignore` `*.preview.png` и убрать `temp_preview.png` из индекса;
- перенести пример картинки в `docs/assets/`.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана |
| --- | --- |
| Оставить временный файл, но в `%TEMP%` | Проблема гонок и лишнего I/O остаётся, live-превью не появляется. |
| `WriteableBitmap` вместо Skia | Ограниченные возможности рисования, отдельный путь рендера от экспорта. |
| Рендер в память через `SKBitmap`, затем конвертация в `BitmapSource` | Лишняя копия на каждый кадр; `SKElement` рисует напрямую быстрее. |
