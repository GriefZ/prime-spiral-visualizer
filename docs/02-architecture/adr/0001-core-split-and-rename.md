# ADR-0001. Разделение на Core / Rendering / Cli / App и переименование проектов

- **Статус:** принято
- **Дата:** 2026-09-19
- **Контекст:** проект вырос из одноразового скрипта «сгенерировать одну картинку». Сейчас в решении три проекта, и все три смешивают слои: `SpiralMaker` одновременно считает простые числа, раскладывает координаты, хранит стиль и экспортирует PNG; консоль и WPF-ViewModel дублируют генерацию простых чисел; UI-логика завязана на временный файл. Имена `SpiralMaker` и `PrimeSpiralVisualizer` описывают прототип, а не продукт, который развивается в студию визуализации чисел.

## Решение

Перейти к структуре:

```text
src/
  BeautyOfNumbers.Core/           (net8.0)
  BeautyOfNumbers.Rendering/      (net8.0)
  BeautyOfNumbers.Cli/            (net8.0)
  BeautyOfNumbers.App.Wpf/        (net8.0-windows)
tests/
  BeautyOfNumbers.Core.Tests/
  BeautyOfNumbers.Rendering.Tests/
BeautyOfNumbers.sln
```

- `SpiralMaker` разделяется: математика → `Core`, Skia-рендер → `Rendering`.
- `PrimeSpiralVisualizer` → `Cli`.
- `PrimeSpiralVisualizerUI` → `App.Wpf`.
- Файлы переезжают через `git mv`, чтобы сохранить историю.
- Решение о смене рендер-технологии — [ADR-0002](0002-skiasharp-renderer.md).

## Последствия

Проще:

- математику можно тестировать и использовать без UI;
- CLI и студия используют один код;
- границы зависимостей проверяемы (ядро без графических пакетов);
- имена соответствуют продукту и не мешают добавлять раскладки.

Сложнее:

- один большой рефакторинг-коммит (или серия мелких, но с временно нерабочим состоянием);
- нужно обновить `.vscode/settings.json`, ссылки в документации и привычные пути;
- история файлов сохраняется только при аккуратном `git mv`.

Задачи:

- удалить дубли генерации простых чисел из консоли и ViewModel;
- закрепить правило зависимостей в [overview.md](../overview.md);
- после M0 ни один проект, кроме `App.Wpf`, не ссылается на WPF.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана |
| --- | --- |
| Оставить имена и слои как есть, рефакторить постепенно | Дублирование и смешение слоёв закрепляются; тесты остаются неудобными. |
| Оставить имя `SpiralMaker` для рендера | Название не отражает суть: ядро — не «делатель спиралей», а визуализатор чисел; продукт шире одной раскладки. |
| Один проект с папками | Зависимости не видны компилятору; ядро легко случайно завязать на WPF. |
