# ADR-0002. Собственный рендер на SkiaSharp вместо OxyPlot

- **Статус:** принято (вступает в силу в M1; до этого прототип живёт на OxyPlot)
- **Дата:** 2026-09-19
- **Контекст:** текущий `PlotUtils.CreatePlot` создаёт отдельный `ScatterSeries` на каждую точку — до 100 000 серий на изображение, что даёт квадратичные накладные расходы и лишние аллокации. Дополнительно:

  - OxyPlot заточен под графики: полярные оси не выражают прямоугольную (Улам) и гексагональную раскладки;
  - живое превью в WPF требует быстрого рендера миллионов точек, а WPF-контекст OxyPlot не использует Skia;
  - превью и экспорт должны идти через один пайплайн, иначе картинка на экране и в файле различается;
  - для арт-инструмента оси, сетки и легенды не нужны, а полный контроль над стилем точек — нужен.

## Решение

Писать собственный рендер на `SkiaSharp`:

- `Core` отдаёт `Scene` — плоский массив точек в мировых координатах;
- `Rendering` рисует сцену на `SKCanvas` с учётом `Viewport` и стиля, группируя точки в батчи по цвету и квантованному размеру;
- превью — `SKElement` в WPF, экспорт — `SKSurface` → PNG;
- панорама и зум реализуются в контроле превью как изменение `Viewport`;
- зависимость `OxyPlot.SkiaSharp` удаляется из решения.

## Последствия

Проще:

- один рендер для экрана и файла, полный контроль над стилем;
- предсказуемая производительность: батчи, отсечение, плоские массивы;
- раскладки любой геометрии (полярные и декартовы) без борьбы с осями;
- `Rendering` не зависит от WPF и пригоден для CLI.

Сложнее:

- авто-масштаб, панорама и зум — своя реализация (десятки строк, но свои);
- нет готовых осей/заголовков — и не нужны (см. non-goals);
- подписи чисел (`showAnnot` в прототипе) не переносятся; если понадобятся — отдельная задача.

Задачи:

- реализовать `SceneBuilder`, `ISceneRenderer`, `PngExporter` ([rendering.md](../rendering.md));
- бенчмарки 100k/1M/10M до и после;
- удалить `OxyPlot.SkiaSharp` из `Directory.Packages.props`/csproj.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана |
| --- | --- |
| Оставить OxyPlot, сгруппировать точки в 2–3 серии | Быстрый выигрыш, но WPF-контекст OxyPlot остаётся узким местом; полярные оси не покрывают Улам/гекс; контроль стиля ограничен. |
| OxyPlot + `OxyPlot.SkiaSharp.Wpf` для превью | Экспериментальность и связность с версиями; две модели рендера вместо одной. |
| OxyPlot только для экспорта, Skia для превью | Два пайплайна → расхождение картинок; двойная поддержка. |
| WriteableBitmap + WPF-рисование | Нет удобных батчей и антиалиасинга такого качества; медленнее Skia на больших объёмах. |
