# Сценарии использования

Обозначения: **UC** — сценарий, **M** — веха, в которой сценарий должен работать ([roadmap.md](roadmap.md)). Статусы: ✅ работает, 🚧 в работе/прототип, ⏳ запланировано.

## UC-01. Сгенерировать и сохранить арт ✅ (прототип, будет переработан в M1–M2)

**Актор:** пользователь студии.

**Предусловие:** приложение запущено, доступна папка для сохранения.

**Основной поток:**

1. Пользователь задаёт диапазон чисел (по умолчанию 1..100 000).
2. Выбирает раскладку (по умолчанию архимедова).
3. Настраивает стиль: фон, цвет простых, цвет составных, размер точек.
4. Превью обновляется автоматически.
5. Нажимает «Save Image», выбирает файл, получает PNG высокого разрешения.

**Альтернативы:**

- Число вне допустимого диапазона → кнопка сохранения заблокирована, показано пояснение.
- Генерация отменена пользователем → состояние возвращается к предыдущему превью, ошибок нет.
- Ошибка записи файла → диалог с причиной; приложение остаётся работоспособным.

**Критерии приёмки:**

- превью не использует временные файлы;
- сохранённый PNG детерминирован: тот же пресет даёт тот же файл;
- экспорт не блокирует UI: окно отвечает на действия, есть прогресс и отмена.

## UC-02. Интерактивно подобрать параметры ✅ (M1, метрики подтверждены)

**Актор:** пользователь студии.

**Предусловие:** открыт проект/пресет (или значения по умолчанию).

**Основной поток:**

1. Пользователь «крутит» параметры: диапазон, цвета, размер точки.
2. Превью перестраивается автоматически: сборка и отрисовка 100 000 точек укладываются в 100 мс ([vision.md](vision.md)); после последнего изменения параметра действует debounce 200 мс ([build-and-run.md](../03-guides/build-and-run.md)).
3. Панорамирование — перетаскивание ЛКМ, зум — колесо к курсору; вид не сбрасывается при смене параметров. Пробел + drag не реализуется до появления конкурирующего инструмента на ЛКМ.
4. Двойной щелчок — сброс вида.

**Критерии приёмки:**

- изменение параметра не блокирует UI-поток;
- при быстрых изменениях в очереди не накапливается больше одной отложенной перерисовки (debounce);
- тяжёлая перерисовка отменяется при следующем изменении параметра.

## UC-03. Сохранить и загрузить пресет ✅ (M2)

**Актор:** пользователь студии.

**Основной поток:**

1. Пользователь настраивает удачную комбинацию параметров.
2. «Save Preset» → имя → JSON сохраняется в `%AppData%\BeautyOfNumbers\presets\`.
3. Через любое время (в том числе после перезапуска) пользователь выбирает пресет из списка.
4. Параметры восстанавливаются, превью соответствует сохранённому. Загрузка применяется сразу, без подтверждения потери изменений; имя текущего пресета показывается в заголовке окна.

**Альтернативы:**

- Файл пресета повреждён или новее поддерживаемой схемы → файл пропускается при чтении, остальные загружаются; явный Refresh показывает одно агрегированное сообщение.
- Конфликт имён → подтверждение перезаписи; отказ оставляет существующий файл без изменений.
- Пресет использует неподдерживаемую раскладку или выходит за лимиты UI → сообщение, текущее состояние не меняется, файл остаётся в списке.
- Удаление пресета — через меню с подтверждением; текущее имя в заголовке сбрасывается, если удалён открытый пресет.

**Критерии приёмки:**

- JSON имеет поле `schemaVersion`; несовместимые версии обрабатываются явно;
- круговой прогон «сохранить → загрузить → сохранить» даёт идентичный JSON (порядок полей стабилен для одного и того же состояния).

## UC-04. Пакетная генерация через CLI ⏳ (M3)

**Актор:** автор проекта.

**Основной поток:**

1. `beauty-of-numbers render --preset spiral.json --output out.png`
2. Команда возвращает код 0 и создаёт файл; код 1 и сообщение — при ошибке.

**Критерии приёмки:**

- CLI использует то же ядро и рендер, что студия (никакой отдельной реализации);
- работает без установленной графической оболочки;
- есть `--help` и валидация аргументов.

## UC-05. Сравнить раскладки ⏳ (M2)

**Актор:** пользователь студии.

**Основной поток:**

1. Пользователь выбирает раскладку из списка: архимедова, Сакс, Улам, гексагональная.
2. При прочих равных условиях видит, как один и тот же диапазон чисел выглядит в разных раскладках.

**Критерии приёмки:**

- смена раскладки не меняет числа и стиль;
- каждая раскладка описана в [../04-math/layouts.md](../04-math/layouts.md);
- новые раскладки добавляются без изменения UI-кода (регистрация в ядре).
