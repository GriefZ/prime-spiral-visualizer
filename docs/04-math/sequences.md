# Числа и последовательности

Документ описывает математическую основу: какие числа использует проект, как определяется простота и почему это важно для производительности.

## Диапазон чисел

Базовый сценарий — целые числа из диапазона `[Start, Start + Count)`. Диапазон задаёт пользователь; «только простые» — это фильтр отображения, а не другой способ генерации.

Ограничения:

- значения — `int` (до 2 147 483 647), практический предел рендера ниже;
- до 10^8 чисел решето строится за секунды и помещается в память;
- выше 10^8 потребуется сегментированное решето — заложено как возможное развитие, не входит в M0–M3.

## Простые числа

Простое число — натуральное число больше 1, имеющее ровно два делителя: 1 и само себя.

Полезные факты для проекта:

- **Плотность.** Количество простых до `n` — это `π(n)`, асимптотически `n / ln n`. На 10^6 их 78 498; на 10^8 — 5 761 455. Это определяет, какая доля точек на картинке будет «главным» цветом.
- **2 — единственное чётное простое.** Дальше все простые нечётные, что создаёт видимые закономерности в раскладках.
- **Простые в арифметических прогрессиях.** Теорема Дирихле: если `gcd(a, d) = 1`, прогрессия `a, a+d, a+2d, …` содержит бесконечно много простых. Именно поэтому простые «любят» определённые направления в спиралях.

## Как определяется простота

| Метод | Сложность | Где используется |
| --- | --- | --- |
| Пробное деление | `O(√n)` на число | `ReferencePrimeClassifier` — только в тестах, как эталон |
| Решето Эратосфена | `O(N log log N)` | `SievePrimeClassifier` — продакшен |
| Сегментированное решето | `O(N log log N)`, память `O(√N)` | Возможное развитие после M3 |

### Решето Эратосфена

1. Заводим битовую таблицу для чисел `2..limit`.
2. Начинаем с `p = 2`; все кратные `p` (от `p²`) помечаем составными.
3. Следующее неотмеченное число — простое; повторяем до `p² > limit`.

Оптимизации, заложенные в дизайн:

- **Только нечётные числа.** Чётные кроме 2 не рассматриваются: таблица сжимается вдвое. Для 10^8 — примерно 6,25 МБ.
- **Битовая упаковка** (`ulong`-слова) вместо `bool[]`: ещё в 8 раз меньше памяти, дружелюбнее к кэшу.
- **Старт с `p²`:** меньшие кратные уже помечены меньшими простыми.

### Текущее состояние

Дублирование устранено в M0: продакшен-код везде использует `SievePrimeClassifier` (odd-only bitset), а `ReferencePrimeClassifier` (пробное деление) остался в ядре только как эталон для тестов. Ни UI, ни CLI, ни рендер не считают простые самостоятельно.

## Классы чисел и цвет

Сцена хранит `ColorIndex` — индекс в палитре, а не сам цвет. Сейчас классов два:

| Индекс | Класс | Цвет по умолчанию |
| --- | --- | --- |
| 0 | Простые | красный / пользовательский |
| 1 | Составные | серый / пользовательский |

Дизайн ядра допускает больше классов (близнецы, палиндромы и т.д.), но новые классификаторы вне рамок M0–M3 — см. [non-goals.md](../01-product/non-goals.md).

## Почему на спиралях видны паттерны

Ключ — делимость на малые числа. В архимедовой раскладке `r = n`, `θ = n` число `n` попадает в точку с углом `n mod 2π`. Числа, кратные 2, 3, 4, …, ложатся на семейства спиральных лучей; простые, не делящиеся ни на что, кроме себя, «выпадают» из этих лучей и образуют собственные кривые. Чем больше диапазон, тем заметнее структура — поэтому производительность и является продуктовой фичей, а не только технической.
